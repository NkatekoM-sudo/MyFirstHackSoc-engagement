# MyFirstHackSoc-engagement
SOC internship Portfolio-41 verdicts showcasing incident analysis, detection workflow and security reporting.

This repository is a hands on virtual internship with a Soc engagement environment I was an employee for a virtual client named Cloudora and I had been working with queues on Service Now as a intern SOC analyst.
The routine I ran for every alert was:
I would open an alert and read the handover first before reading the alert so I can be updated about the shift.
then I would read the alert and answer the first question of my seven part verdict structure about what is the alert, where did it come frome and at what time was it made, then I would write a two part scenario about if it was malicious what would be the impact and if it was benign, what would it be, then I would move on to reading the evidence in Sentinel KQL to prove if this alert is a true positive or not and if it is what is the impact, and to answer why it was fired then I won't give my verdicts if it was false positive or true positive or if it needs to be Escalated. There was an incident I had started to triage then I discovered that it was a duplicate alert of one I had already closed. 
what I would do differently is take the time to learn more about identity risk sufficiently and I would concentrate on breaking down the alert first in to three parts:
1. what happened 
2. what was found
3. why was the alert triggered
